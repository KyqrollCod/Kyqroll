# 仕様：ココナラ「ヒアリング不要・72時間納品」講師・コーチ・教室向けLP制作

この事業の仕様はこのファイルだけに書く。CLAUDE.md とスキルはここを参照するだけにする。
最終更新: 2026-11-17 夜（集客施策 §8b 追加。採用決定: 2026-11-16）

## 1. 事業の要点
- 売り場: ココナラ（出品型）。実績0のうちは公開依頼への提案を主な集客経路にする（§8b）。
- 対象: 個人の講師・コーチ・教室（ピアノ・英会話・書道・料理・プログラミング教室、キャリア/ビジネスコーチ、
  オンライン講座など）。目的は「体験・無料相談の申込」。
- 対象外（受けない、または要判断）: 医療・治療院・整体・美容・健康食品・サプリ・投資・副業塾・
  恋愛/占いの効果保証。薬機法・医療広告ガイドライン・景品表示法・金融関連規制の表現リスクが高いため。
- 差別化: 通話ヒアリングなし（トークルームの質問15問に答えるだけ）、72時間で初稿、修正2回込み、
  AIっぽくないデザイン（persona-lp / unslop の手順）。
- 作業者: Claude が一貫して担当する（制作・出品・返信・納品・報告）。オーナーは定期報告を読む。

## 3. 納品物と公開方法
- 納品物: `index.html` 一式（CSS・画像込みのフォルダ）をzipにしたもの、公開手順書（PDF/テキスト）、スクリーンショット（スマホ・PC）。
- 申込ボタンの行き先は購入者の既存の窓口（LINE公式、Googleフォーム、予約サイト、メール）。
  フォームの裏側（サーバー）は作らない。
- 公開は購入者自身が行う。手順書は無料の静的ホスティング（例: Netlify Drop にフォルダをドラッグ）向けに書く。
  公開代行のために購入者のアカウント情報を受け取らない。
- 出品フォームの制限（2026-11-17 確認）: カテゴリ「Webサイト制作・Webデザイン > LP作成・ランディングページデザイン」、
  タイトル23文字＋末尾「ます」固定・1文字目に記号不可、キャッチコピー30文字、サービス内容1500文字（600字以上推奨）、
  購入にあたってのお願い1000文字、有料オプション名60文字・最大10件、よくある質問 各400文字・最大10件、画像最大10枚、価格は1,000円刻み。
- 要確認（初回の納品前に確かめて、このファイルを更新する）: ココナラの納品で添付できるファイル形式と容量、Netlify Drop の現状。

## 4. 権限（オーナーの決定 2026-11-16）
オーナーは、出品の公開と返信の送信を Claude に任せた。定期報告をオーナーが読むことで確認とみなす。

**事前承認なしで Claude が行い、報告に記載するもの**
- 出品の作成・編集・公開・一時停止、出品画像（サムネイル）の作成
- トークルーム・見積り相談・DM・公開依頼への返信と提案（§2 の価格表の範囲内）
- 制作、納品、修正対応、レビューへの返信
- このリポジトリ内の制作物・記録の更新（commit/push/PR/merge）

**「要判断」として報告に上げ、オーナーの返事があるまで実行しないもの**
- キャンセル・返金・値引き・価格表の変更・無料対応
- お金がかかる操作（広告、有料プラン、有料オプション、ドメイン購入など）
- §1 の対象外業種の依頼を受けるかどうか、規約や法令に触れそうな依頼
- アカウント設定、本人確認、振込申請、退会、パスワードの変更
- クレーム・紛争・法的な請求への対応

**絶対にしないもの**
- ココナラ外への誘導や連絡先の掲示（メール・LINE・SNS・Google Drive などの共有を含む）。ココナラ規約第18条、禁止行為一覧
- 架空の実績・お客様の声・レビュー、虚偽の表示（規約第18条1項5号）
- 購入者の情報を取引の目的以外に使うこと（規約第18条1項3〜4号）
- 他人の著作物・商標・写真の無断使用、実在の他社LPのコピー
- アカウントのパスワードをチャット、ファイル、環境変数に書くこと

## 5. 規約上の論点（2026-11-16 に利用規約の本文を確認済み）
- 第13条2項22号「当社が認める場合を除いて…自動的に応答する等の機能を有する装置、ソフトウェア、アルゴリズム等を利用する行為」は禁止。
- 第6条2項「当社サービスの利用は、利用会員自身が行うものとし」。第74条2項はパスワードの第三者への貸与を禁止。
- 対応方針: ログインはオーナー本人が自分のPCのブラウザで行う。Claude はそのブラウザを
  オーナーの道具として操作し、パスワードを受け取らない。
- **返信の送信（オーナーの決定 2026-11-16: B）**: 最初から Claude が返信を送信する。オーナーはアカウント制限のリスクを承知している。
- **運営への問い合わせはしない（オーナーの決定 2026-11-16）**: 初期運用で目をつけられるリスクを増やさないため。
  文案 `docs/coconala/inquiry-to-coconala.md` は保留として残すだけで、送らない。
- **送信を止める条件**: ココナラから警告・制限・規約に関する通知が届いたら、その時点で送信を止め、次の報告の要判断の先頭に上げる。
- **A/B の再判定**: 収益が安定したら、A（Claude が文面を作りオーナーが送信、または運営に確認してから自動送信）と
  B（現状）をあらためて判断する段階に移る。目安は「月の受注3件以上（§8 の90日目標）を2ヶ月続けて達成」。
  達成した月の週次報告で、要判断の先頭に「A/B 再判定」を上げる。問い合わせを送るかどうかもこのときに決める。
- 本人確認、出品者登録、振込口座の登録はオーナー本人が行う（売上金の申請には本人確認が必須）。

## 5b. 既存アカウントの整理（オーナーの許可 2026-11-16）
- オーナーの既存アカウントを使う。プロフィールは Claude が書き換えてよい（文案 `docs/coconala/profile.md`）。
- 古い出品は削除せず「非公開（停止）」にする。過去の取引・評価・メッセージは消さない（実績と記録のため）。
- 古い出品に実績やレビューが付いている場合、その出品を流用（タイトル・本文の差し替え）するかは、カテゴリが合うときだけにする。
- 本人確認・振込口座・メールアドレス・パスワード・通知設定以外のアカウント設定は変えない（§4 の要判断）。
- 整理の前に、現状（出品の一覧と状態、プロフィール、未対応のメッセージ、進行中の取引）を ops-log に要旨で記録し、
  最初の報告にまとめる。進行中の取引や未返信があれば、新規の作業より先に対応する。

## 8b. 集客施策（オーナーの決定 2026-11-17「追加して」）
受け身（受信箱の監視だけ）では新人の出品は見つからないため、次の2つを定期タスクで回す。

### 8b-1. 公開依頼への提案（毎日、`coconala-proposals`）
- 「仕事を探す」の公開依頼から、LP・ランディングページ・ホームページ（1ページ）の依頼を探す。
- 提案してよい条件（すべて満たすもの）: §1 の対象業種／静的なLP1ページで足りる（WordPress構築・サーバー・EC・
  フォーム裏側・多ページサイトは対象外）／予算の上限が 20,000円 以上／希望納期まで 5日以上／
  ココナラ外での連絡や作業を求めていない。
- 提案額は §2 の価格表どおり（モニター枠が残っていれば 20,000円、なければ 40,000円＋必要なオプション）。
  予算に合わせた値引きはしない（値引きは要判断）。
- 1日3件まで。同じ依頼者に重ねて提案しない。依頼文に合わせて1件ずつ書く（定型の一斉送信はしない。規約第13条2項22号への配慮）。
- 文面は `docs/coconala/replies.md` の「公開依頼への提案」。送信前チェックを通す。
- ココナラ側に提案数の上限や有料枠がある場合は無料の範囲だけ使う（有料は要判断）。
- ops-log に依頼ID・業種・提案額・結果を1行ずつ書く（依頼者名・本文は書かない）。

### 8b-2. 出品の週次改善（毎週月曜、`coconala-weekly-report`）
- 出品A・Bの閲覧数・お気に入り・見積り相談を `docs/coconala/metrics.md` に週ごとに記録する。
- 公開から7日以上たち、直近7日で「見積り相談0 かつ お気に入り0」または「閲覧数が前週以下」なら、
  1週に1か所だけ変える（順番: サムネイル → タイトル → キャッチコピー → サービス内容の冒頭）。
  価格は変えない（出品価格の変更は §2 で許可済みだが、効果を分けて測るため、価格は 30日判定まで据え置く）。
- 変えた前後の文言は `docs/coconala/listings.md` に反映し、metrics.md に「変更点」として残す。翌週の数字で効果を見る。
